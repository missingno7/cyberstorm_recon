## Codegen findings and negative evidence

All observations use pinned Watcom 10.6 wpp386 via tools/cc.py (including try/variants/promote wrappers).

1. **Small helper return width matters even without an explicit truncate.**
   ot-oe, SurfaceMidpoint: int return gave D4 (register clear/load order); unsigned short with
   (first+second)>>1 is STRICT 32 bytes. SurfaceAverage is STRICT 48 bytes with unsigned-short return
   and the simple left-associated sum >>2. Evidence: surface_mid_width.tpl.c and
   surface_average_width.tpl.c. These are local verified facts, not a rule that every clamp helper is short.
2. **Geometry operators need the signed operation and reference return context.**
   Struct point copy, signed y = -y*2, and reference-returning +=/-= reproduce the complete 192-byte
   DisplayPointToScreenScaled. Unsigned y multiplication and void-returning geometry operators did not.
   Evidence: display_points*.txt and final status_display.txt.
3. **Typed data pointers change addressing selection.**
   SurfaceGridLayout's shift at 0x50, unsigned width at 0x94, and byte pointer at 0x98 give STRICT
   SurfaceGridValue (80 bytes). Integer-address arithmetic was D2 even after restoring mask/shift order.
   Setter is a counterexample: it remains DIFF, so the type correction alone is not sufficient there.
4. **Constructor boundary preserves rectangle temporary stores.**
   A ViewRect(x,y,w,h) constructor retains the 16-byte local rectangle in MapContainsPoint; a plain
   aggregate let Watcom remove it. The constructor form is STRICT 240 bytes.
5. **Inline accessors affect scalar register context.**
   MapOrigin(self) returns the grid origin through EAX and closes the 2-byte register differences in
   PrepareDeathMap/MapNearestAt. A source pointer for the point copy closes MapGetView's extra EBX save.
   All three are strict in the retained TU.
6. **This TU's useful inline threshold is 150.**
   -oe/default100 keeps MapContainsPoint out of MapPickVisit (48-byte caller versus target 256).
   -oe=150 inlines it while retaining MapInitialize's call to SetFastView. Returning explicit 1/0 from
   MapPickVisit avoids a redundant saved result and gives STRICT 256 bytes.
   -oe=200 also inlines SetFastView into MapInitialize (272 bytes versus target 96), rejected.
   Evidence: map_oe150.txt, map_oe200_rect.txt, map_pick_explicit.txt, final map promotion.
7. **Surface loader: default arguments and reloads are required.**
   The existing ResMgr::Load(char*, unsigned, int*, unsigned) declaration with three defaults restores
   the EBP frame. Reloading object dimensions after calls reduces locals from 16 bytes to the original 4.
   Allocation width*width + depth*depth*3, not the commuted tree, and (depth*depth)*2 for copy counts
   produce STRICT 464 bytes. Evidence: surface_load_defaults.diff.txt, surface_load_reloads.diff.txt,
   surface_load_math.tpl.c (two strict alternatives).
8. **Raw addresses are not relocated references.**
   Declaring SurfaceScaleValues as external data closes SurfaceStaticValue's previous relocation-only
   failure and implies 4904d4. DisplayConstructArray's raw addresses remain a negative example.
9. **Source/decompiler audit corrections.**
   Surface assertion literal is terr\tsurface.c; physical lines are 795/799/805/832. Display/area assertions
   are 113/143. show.py proves the sprintf literal is scape%d.dat although the Ghidra string symbol is
   spelled scape_d_dat. SurfaceRandomize's initial random fill uses bounds grid[2],grid[3] and scatter
   count uses grid[0],grid[1]; the inherited source swapped the high bounds. Its fill destination is
   captured before RandomRange/memset. These semantic repairs remain DIFF and are not counted as matches.
10. **Proof limitation for an object-leading table.**
    SearchGetCost exactly matches through d3c3, but compare extends it to the next function d3f0 and
    rejects the next object's leading table. No verifier changes, copied tables, padding tricks or
    acceptance overrides were used.
