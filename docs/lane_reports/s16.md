## Compiler findings and negative evidence

All measurements use pinned Watcom 10.6 C++, -4s -s -bm with -oe unless stated otherwise.

- A field read through an inline accessor can change allocation far beyond the load: replacing
  `s->selected->logic` with `s->selected->Logic()` fixes ReportSelect's first allocator discrepancy
  around +c0 and the later global-control allocations. Direct version: 395 bytes/D43; accessor:
  STRICT 395. Evidence: `report_try2.txt`, `report_accessor.txt`, final promotion. This supports
  extending the existing accessor fact to pointer-returning accessors on nested objects.
- A scalar capture of `p->actor` removes the unnecessary EBP save caused by reading the field twice
  across ActorGetByIndex in ReportOpen. Together with the inline MenuNumber align setter, the
  full function becomes STRICT 223. Evidence: `report_open.txt`, `report_try2.txt`.
- The chassis-image helper at 00439d02 returns int, not byte. Declaring byte inserts `and eax,ff`
  before SimAnimSet in ReportSelect. The int prototype removes it; it also makes the native-this
  StorageScreen::Names extent STRICT 111. This is independently corroborated by the now-published
  definition in src/_unknown/tu_004394e0.c. Evidence: `report_select.txt`, `storage_returnint.txt`.
- An explicit top-tested infinite loop with `if(i>=24)break` reproduces StorageVisibleNames's
  bottom `inc; jmp test` shape; the ordinary for spelling puts the increment at the top and is
  117 vs 115 bytes. Evidence: `storage_method.txt`, `storage_vnloop.txt`, final promotion.
- For Render, returning from cases 0/1/3 and putting Draw after the switch produces the observed
  late epilogue; placing Draw in default and using breaks selects an early epilogue. Six full-body
  variants reduced the discrepancy from D611 to D16 before the return-type correction reduced it
  to D4. Evidence: `storage_render.tpl.c`, `storage_renderbest_diff.txt`, `storage_render_this.txt`.
- Negative: replacing the visibility arithmetic with C++ bitfield assignment shortens/narrows it
  and loses matches. Evidence: `storage_bits.txt`, `report_bits.txt`; restored arithmetic is final.
- Deliberate inline-limit check: limits 50,80,100,120,150,200 tested the hypothesis that the remaining
  inlining/spill differences were a threshold issue. Storage best: 23/32 diagnostic extents at 80/100;
  report unchanged at 80..200, worse at 50. No new strict target function resulted. Evidence:
  `storage_inline_sweep.txt`, `report_inline_sweep.txt`. No additional flag sweep was performed.
