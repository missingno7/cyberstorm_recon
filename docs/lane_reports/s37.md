## Codegen facts and negative evidence

All observations below use pinned Watcom 10.6 wpp386, -4s -s -bm plus the stated options.

1. **lsys / -ol:** after source reconstruction, plain leaves a two-byte mov ebx,eax at the actor-loop tail, giving a 436-byte LogicStateValue. Adding -ol enables the original shared assignment/backedge, producing 434 bytes. The adjoining switch table then matches LogicReset too. Full final _TEXT becomes STRICT, 39 functions / 3,317 bytes. Evidence: build/s37/lsys-ol-compare.txt and lsys-promote-final.txt. This is a per-TU finding; -ol is rejected for miss/linkapp.
2. **lsys rectangle construction / defaults:** constructing the local rectangle from raw bounds, then adding 15 to x and subtracting 29 from width, copying it back as one object, and using BriefRender's defaults produces the exact 151-byte ConsoleResize including its 20-byte frame and four movsd copy. Seven forms in lsys-rect.tpl.c: only the raw-bounds-then-adjust form is STRICT.
3. **lsys draw / aggregate copy:** local LogicRect rect=logicTextRect with default render arguments gives the exact 172-byte DrawConsole. Explicit scalar locals, reordering them, const scalars, and reconstructing via the four-argument constructor fail. A volatile-width scalar form was eight bytes off. Seven forms are in lsys-draw.tpl.c.
4. **nested inline accessor / EBP frame:** passing second->Id() directly as an argument to LogicActorCommand reproduces the 85-byte LogicSetActorLink and its EBP frame. This also matches when the final zero argument is explicit. Materializing command first gives the old 84-byte / 51-difference result. Seven forms in lsys-link.tpl.c. Thus default arguments are not the sole possible cause of this frame shape. Matching this function also fixes MapViewPoint's previously one-byte-off shared-tail displacement.
5. **mission inlined index result:** with plain-oe, int offset=table[type]; offset+=boundedItem; return offset gives the required load/add result in the caller. Returning table[type]+boundedItem directly instead folds to an in-memory addition in EDX and shortens the wrappers. Six return forms × two wrapper result types in miss-item-return.tpl.c found both STRICT wrappers: 81 and 77 bytes.
6. **chat inline history body:** a direct-this member helper gives exact inlined history appends; a free helper with a pointer alias left four differing bytes in process_chat. Keep the independent out-of-line append body: a wrapper around the helper changes its allocation and loses the existing match. Evidence: chat-inline2.txt, chat-direct-member.txt, chat-shared.c and final 15-function receipt.
7. **chat stack-relative sprintf arguments:** the two target loads from [esp+18] are separated by a push. They select text and then name. sprintf(log,"[%s]: %s",name,text) makes add_chat_message STRICT at 233 bytes; using text twice leaves 229 bytes / 207 differences. Evidence: build/s37/chat-log-name.txt.
8. **chat loop increment:** ordinary ++index with two direct repeated indexed state-member tests produces target add edx,ebx on the loop edge. That instruction does not establish source +=state. Caching the state gives the wrong saves/allocation; caching a pointer inserts a separate add before the load. Six loop and six field-access forms led to the direct-indexed 84-byte STRICT body. The target's odd state==1 && state==2 condition is preserved.
9. **link static initialization:** real Queue globals with destructors and the 33-element class array emit the 80-byte initializer, correct HIGHLOW sites, state counter, registration data and array type descriptor. Literal placement-new addresses and invented runtime calls are unnecessary. The descriptor also proves destructor ownership beyond the heuristic range.
10. **link queue loop:** an inline HasEntries() scalar result, persistent ready variable updated from MessageDispatch, inline entry Name() getter, and inlined save_link_tick produce the exact 128-byte drain function. A direct while(!IsEmpty()) drops the target boolean normalization; the earlier two-loop spelling kept it in EDX. Six accessor/loop forms in linkapp-drain-access.tpl.c include two STRICT forms.
11. **mission frame probe, diagnostic:** a typed-record pointer alias plus two omitted ClampRange defaults produces Copy's exact 550-byte frame/extent and moves the first mismatch from +4 to +f, but is not STRICT. Six pointer/reference/member forms and six banner-helper forms do not establish the historical API. Treat the default values and local home layout as hypotheses.
