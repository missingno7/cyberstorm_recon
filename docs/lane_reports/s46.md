# Lane s46: hand-assembly reconstruction

STATUS: partial. All 12 routines are reconstructed in eight readable assembly files. All eight pass assembly policy and assemble with pinned WASM 10.6. No routine is STRICT: the current assembler selects the opposite direction bit for 162 register-register instructions (284 differing bytes). All eight promotion dry runs completed, each with zero strict functions. No publication or acceptance claim.

## Assembler evidence

**The original assembler is not uniquely identified. WASM 10.6 with the pinned `asm` profile does not reproduce the original register-register encoding convention.** MASM 6.x/TASM remain hypotheses, not tested or identified toolchains; no unpinned assembler was run or wired into the project.

The original uses the register-destination direction-bit form for all 162 affected two-register instructions. WASM selects the r/m-destination form and exchanges the ModRM register fields. Both decode to the same instruction, but STRICT requires the original bytes. The current WASM interface exposes no instruction-direction selection; changing instructions into byte emission would violate the work order.

[encoding_residue.tsv](encoding_residue.tsv) lists **every** affected VA, both byte encodings, and both decoded instructions. A diagnostic audit verifies that every non-fixup byte difference is this two-byte direction/ModRM substitution. It is not a STRICT or semantic-execution certificate.

Other fingerprints:

- `ENTER 0,0` = `C8 00 00 00`, `LEAVE` = `C9`, stack register saves, `PUSH DS`/`POP ES`, string instructions, BSWAP, SHRD/SHLD and XCHG forms reproduce exactly.
- All branch lengths and displacements reproduce: e.g. `004811b8: 7C 0A` versus `004811c6: 0F 8C AE 00 00 00`. Local JMPs are explicitly SHORT; WASM relaxes conditional jumps to the original short/near forms.
- Immediate widths reproduce: `add ebx,63` = `83 C3 3F`, `test ebx,1` = `F7 C3 01 00 00 00`, and `sub eax,40000000h` = `2D 00 00 00 40`.
- The NOP at `00435c5d` is reproduced with `EVEN`. A separate WASM `ALIGN 4` probe needing three bytes emits `8D 40 00`; there is no comparable three-byte internal alignment run in these ranges, so this does not identify the original assembler.
- Final negative probes: `.386/-3s`, `.486/-4s`, `.586/-5s` and explicit `DWORD PTR`/`BYTE PTR` register qualifiers all preserve the unwanted forms. `-zcm` fails: `Unknown option zcm. Use /? for list of options.`

All assembly invocations use `tools/cc.py` and its pinned hash checks.

`gui/flic_pixels.asm` and `gui/flic_packed.asm` derive their directory/stem from the explicit `gui\flic.c` caller path; both are also called by `pack\unpack.c`. `pack/unpack.asm` follows its sole known caller path `pack\unpack.c`. Terrain, line clipping, atan and trig have no uniquely evidenced calling source path, so use the requested `_unknown/asm_<VA>.asm` convention. The trig routines have several callers, including `sim\anim.c`; that does not establish their own original source path. Caller sites and `tools/symbols.py show VA` results are in [callers.json](../../build/s46/callers.json) and [symbols.txt](../../build/s46/symbols.txt).

Existing names are retained. In particular, C-linkage `FixedSin` at 0047f9a0 and `FixedCos` at 0047f9d9 conflict with another pre-existing C++ `FixedSin` hypothesis at 0047f9d9. The table begins with 16384 and the first routine has no quarter-turn subtraction, so the first computation is cosine-shaped. No binding was renamed. `FixedTan` at 0047fa17 is a new working label. `UnpackLzw` is the existing label for the byte-run/literal decoder; it is not algorithm identification.
