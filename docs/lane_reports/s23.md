## New compiler/proof facts for integrator review

1. **plain, nested default arguments:** with SimPreviewCost's trailing default already omitted, spelling `HercFormatItem(manager, PopFindItem(manager,itemId), itemId)` using the two nested omitted defaults produces the required EBP frame and a STRICT 186-byte selection handler. Spelling those flags explicitly removes the frame (183-byte diagnostic). This narrows the existing ?two defaults on one call? rule: defaults in nested calls can also affect the frame. It does not establish a general count rule for all functions.
2. **plain-oe, inline scalar-to-byte setter:** `shieldNumber.align=1` emits an immediate byte store and makes OpenShield 163 bytes. In-class `SetAlign(int value){align=value;}` called with 1 emits `mov eax,1` followed by the AL store, giving the original 166-byte STRICT function. Trigger: inline argument/field conversion, not an extra side effect.
3. **plain-oe, squared point terms:** in the 155-byte SetAim, `ISqrt(point.y*point.y + point.x*point.x)` has four register-byte differences; `ISqrt(point.x*point.x + point.y*point.y)` is STRICT. The point members are signed long; ISqrt takes unsigned. Thus the earlier blanket observation that square-sum operand order is canonicalized does not apply universally. Evidence: six-way `aim_variants.c`, choices 1 and 5 STRICT; the other four differ by 4 bytes.
4. **plain-oe, in-class nonvirtual screen destructor:** defining it inside the class emits a separate 12-byte COMDAT. An out-of-class definition leaves it adjacent in _TEXT and makes the prior callback extent consume the wrong boundary. The in-class form accounts for the three zero linker-fill bytes before `4451e8`; no padding is manufactured in source.
5. **switch cases sharing default:** chooser cases 0,3,4 explicitly sharing the default are necessary to produce the five-entry table at `4443d0`. Keeping only cases 1 and 2 produces a comparison tree. The table is proven as part of the preceding drawer extent and as an external switch table for GetValue; masked similarity is not counted.
6. **descriptor binding diagnosis:** the `443ed0` code was already byte-equal but could not be STRICT while its own descriptor was forced to the unrelated 0x28-byte descriptor at `48df88`. The distinct observed 0x2c-byte descriptor at `48dbe8` plus reused existing function linkage resolves the proof without changing config or weakening checks.
