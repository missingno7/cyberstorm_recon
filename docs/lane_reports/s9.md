## New codegen facts and negative experiments

1. **Inlining limit is discriminating in the VR screen (verified reproducing configuration).** Context: pinned wpp386 10.6, `-4s -s -bm`, complete candidate. Trigger: `-oe`/`-oe=100` inlines `BiodermStatsScreen::SetControls` into Open, Render, MessageDone, and Message, placing additional switch tables before callers and changing their extents. `-oe=80` and `-oe=90` retain those calls while still expanding UpdateCredits, Message, and DrawMessage as observed. Evidence: `build/s9/e7_sweep.txt` tests 10 limits (10 through 100); 80 and 90 have zero differing code bytes, while 40 through 70 have 268 differing bytes and 100 has 2,139 in the pre-literal-fix candidate. The final `-oe=80` gate receipt proves 18 functions / 3,390 bytes; the default `plain-oe` negative receipt proves only 10 / 1,673. This establishes a reproducing limit interval, not a claim that the original command line used exactly 80. Explicitly marking the three helpers `inline` under plain reproduces their callers but drops their required uncalled copies (`build/s9/e7_inline.txt`). Duplicating the three hidden-state loop bodies prevents excessive inlining but grows SetControls to 288 bytes (`build/s9/e7_cases.txt`), so that source family was rejected.

2. **A later global's width can change an earlier register allocation (verified A/B/C).** Context: complete list TU, `plain-oe`. Trigger: declare `biodermListVisible` as byte, unsigned short, or int while keeping both assignments equal to zero. Only byte matches the oracle byte stores at `0040dabd`/`0040dbc3` and the surrounding function. The first Render difference with the int declaration is already at `+0x318`: original reuses EBX for displayed credits; the candidate uses EDI. Thus an allocator mismatch can originate from a wrongly typed store hundreds of bytes later. Evidence: the six full-body combinations in `build/s9/d2_width_bounds.tpl.c`, run with variants.py; results in `build/s9/d2_width_bounds.txt`. Byte gives STRICT Render; int gives 388 differing bytes, and unsigned short 418. The width changes also shift predecessor switch tables and cause two bytes to differ in the otherwise unchanged Buy function.

3. **Equivalent signed range tests preserve their written boundary (verified).** Context: same six-combination experiment. Trigger: `kind<17 || kind>19` versus `kind<=16 || kind>=20`. The former reproduces the original `cmp esi,0x11; jl ...; cmp esi,0x13; jle ...`; the latter uses constants 0x10/0x14 and gives four differing bytes in Buy even with the correct byte visibility field. This is source-spelling evidence rather than a flag issue.

4. **Returning the known zero versus the accumulator can affect one branch byte (verified candidate sequence).** Context: medlab TotalCost, plain-oe, initialized total before Count, separate additions for events 0x73/0x77/0x75. A common `return total` produced 152 bytes with the count-zero branch targeting `+0x8f`, where ESI is copied to EAX. The original branches directly to the epilogue at `+0x91`; returning literal zero on the zero-count path reproduces it. Evidence: `build/s9/f4_try2.txt` (one differing byte) and `build/s9/f4_try3.txt` (STRICT).

5. **Full TU prefix restores switch-table alignment (verified).** Medlab Update's code was byte-identical but had a shorter extent before the full Render switch was present. With Render present but the initializer omitted, table padding was still displaced because the object-relative offset differed modulo four. Restoring the genuine 305-byte global initializer yielded STRICT Update (118 bytes) and Render (416 bytes), without explicit padding declarations. Evidence: `build/s9/f4_try1.txt`, `f4_try3.txt`, and `f4_try4.txt`. The list and VR receipts likewise include switch tables in predecessor extents.
