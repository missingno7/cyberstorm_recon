## Codegen facts and negatives for integrator review

All observations are for pinned Watcom C++ 10.6. `plain-oe` means `-4s -s -bm -oe`; `ot-oe` means `-4s -s -oxt -bm -oe`. These are context facts, not broad allocator rules.

1. **Pilot accessor boundary, ot-oe:** `sprintf(text, format, actor->Pilot())` with inline `Pilot(){return logic;}` changes the load into ESI and subsequent quiet load/test into ECX, matching SimActorKilled's last four differing bytes. A separate pilot capture after string lookup also matches; capturing it before lookup gives 11 differences. `killed_accessors` six-choice receipt and the final 224-byte STRICT proof are the evidence.
2. **Point construction and comparison operands, ot-oe:** a center point constructed from the two viewport averages supplies the original 0x10 sound frame and screen/center slots. Writing each viewport bound on the left repairs scalar load/compare choices. Reversing the final selected-unit comparison to `g4d2498->unit != g4d249c` completes the 432-byte STRICT body. The same last fix also works through a native unit accessor or a scoped loaded unit; `sound_point_layout`, `sound_bounds`, `sound_final_guard` retain the progression 267 -> 220 -> 42 -> STRICT.
3. **Real count capture, plain-oe:** computing the used `next=n+1` at the output-loop head creates the missing four-byte slot in LogicMapViewUpdate and also repairs the earlier amount/have register roles. An explicit loop guard after that computation restores its pre-test scheduling. A chassis accessor repairs byte widening to EAX. Residue is still 24 bytes, so no general source-order rule is established. Four `mapview_*` families and final aligned diff show the individual effects.
4. **Constructed local point plus marker scalar, ot-oe:** adding an empty default constructor to GridPoint changes inlined local allocation. With a byte marker it loses public SimDrawAction; with an int marker the public body is again STRICT and SimDrawFrame falls to 16 differences. `draw_point_order` tests all eight combinations of ctor/plain point, local order and byte/int marker. Local declaration reversal harms both contexts. No dummy locals or unused argument captures are involved.
5. **Formatter consumption order, plain-oe:** advancing src after expression evaluation and after the outer text/printf consumption, then computing list-index arithmetic before advancing src, gives its exact 428-byte extent and reduces 324 differences to 89. It trades the old correct-sized frame for a four-byte-short frame, so this is a constrained negative result, not a matched solution. Extra register qualifiers, index widths and a list accessor do not remove the allocation residue.
6. **Narrowed negative findings:** int/long costs and natural distinct cost names do not swap FindType's two slots (8 differences remain); member timer return spellings do not prevent the inline EAX return merge; direct/member/reference distance spellings do not fix Depot's register pair or final padding. These are recorded in the named six-choice logs rather than offered as new general rules.
