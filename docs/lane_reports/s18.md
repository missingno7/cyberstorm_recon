## Constructor descriptor identity audit

At 0048e0d8 the oracle's descriptor has code references +1 -> 00464d74, +5 -> 0047e008 (undefined constructor/destructor runtime stub), +9 -> 00464d6c, followed by element size 0xa8. `tools/objdis.py build/s18/lactors.obj --data` shows this compiler emits +1 default ctor, +5 copy ctor, +9 dtor. Both 00464d6c and 00464d74 contain the same five-byte empty-body shape, with linker padding between them.

This supports the hypothesis that 00464d74 is the original default ctor and 00464d6c the dtor, whereas the accepted ledger currently calls 00464d6c LogicActor::$ct. The lane did not rebind or withdraw accepted proof. The initializer is therefore UNBOUND, not STRICT. An integrator should audit this identity before changing the accepted label or claiming the descriptor. Evidence: original `show.py 48e0d8 10`, `show.py 464d6c 16`, and build/s18/lactors_obj.txt / lactors_compare.txt.
