## Compiler findings and negatives for the integrator

All measurements below use pinned Watcom 10.6, C++, `-4s -s -bm`, with `-oe` where stated.

1. **Native destructor declaration versus an aux-named ordinary destructor:** in `UpgradeInitScreen`, the native `FileRecord::~FileRecord` declaration emits `push 0; sub eax,0x3e5`; binding the destructor directly to the ordinary `FileRecord::Release` spelling emits the subtraction before the push. The targets resolve to the same VA, but the scheduling differs. Native declaration gives a STRICT 47-byte screen destructor. A/B: `build/s15/hbupgrad_v1.c` versus final `hbupgrad.c`, receipts `hbupgrad_nativefile.txt` and `hbupgrad_dry.txt`. Do not generalize this scheduling result to arbitrary pragmas.
2. **Mutable stop identifier:** spelling the captured current sound as `old -= 2000; SoundStop(old); SoundRelease(old)` makes the starting function keep it in ESI and emit `sub esi,2000`. Repeating `old-2000` selected an EAX temporary and `lea esi,[eax-2000]`. With typed receiver and both evidenced checks retained, the former gives `HercSetMissionStart` STRICT, 161 bytes. Evidence: `audio_v4.c`, `audio_v6.txt`, final `audio_v9.txt`.
3. **Distinct sequential loop counters:** expanding the stop-all loop into the shutdown body removes an extra zeroing instruction; reusing its index in the subsequent release-all loop still chooses EBX where the original uses ESI. Giving the second loop its own ordinary counter restores all 355 bytes of `f_46b9bd`. A/B: `sound_shutdown.txt`, `sound_shutdown2.txt`, `sound_shutdown3.txt`. This is a context-specific lifetime result, not a register-number rule.
4. **Repeated cache member versus captured buffer:** `if (soundCache[id]) { ++released; soundCache[id]->...Release(soundCache[id]); ... }` reproduces the original ECX receiver and EDI zero temporary. Capturing a separate `SoundBuffer *buffer` produced EAX/ESI instead. The repeated-member form makes `SoundRelease` STRICT, 69 bytes. A/B: `sound_v0.txt` versus `sound_v4.txt`. This also repairs register choices in its inlined copies; their remaining cross-function jumps do not count as strict.
5. **Default arguments:** changing the WAX load from four explicit arguments to `Load(name,0)` (two defaults) restores the original EBP frame and reduces `SoundCreateBuffer` from 689 to 603 bytes in the first test. This corroborates the existing default-argument rule; it is not a new global flag requirement. The function remains parked.
6. **Source pointer for structure copy:** taking `sourceFormat=&resource->format` before setting the sample pointer emits the original early `lea esi,[eax+0xc]`; direct `*format=resource->format` places that LEA after the destination load. Measured inside `SoundCreateBuffer`; not a full-function proof.
7. **Setter wrappers and captured scalars:** passing clamp results through small scalar setter wrappers restores the settings routine's eight-byte stack allocation, separate frequency temporary, and `imul 100; neg` volume shape. Direct multiplication by `-100` and direct member expressions give a four-byte frame and different instruction order. The final routine still differs in receiver/result registers, so this is measured codegen evidence rather than a claimed match.
8. **Later functions affect earlier tail bytes:** changing only the queue routine's reject/return structure changes `SoundLoad` from 376 to 374 bytes and changes the shared target used by the stop/release routines. The original-small-routine bodies can be byte-equal except for one or two displacement bytes and still fail STRICT. Six T receipts record this negative. Repair the whole object context; do not pad, mask, or patch the jumps.
9. **Quick-start initializer negative:** changing all six natural widths/signednesses of the selector constructor's count does not recover the EBX-held constant 14. Constructor wrappers versus name-only external constructor declarations also did not fix it. Do not repeat this hypothesis family without new TU/header evidence.
