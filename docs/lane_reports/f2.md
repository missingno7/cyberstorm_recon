## Shell object ownership

The two shell compilations emit the four assigned functions in individually named COMDAT code segments. The existing pilot screen object already emitted the destructor at 0041231c. Removing the symbol-name pragmas on the native Flic and Surface destructor declarations restores the instruction order on all three cleanup calls.

In the comms screen object, the existing global `g4b20c8` causes Watcom to emit the implicit MenuListButton destructor. It matches all 67 bytes and the associated type descriptor at 0048cf98. A standalone explicit destructor adds a seven-byte store to the vtable pointer. Inline definitions of the two GuiControl virtual methods emit their exact COMDATs in the same comms screen build. The four initial standalone source probes are under `build/f2/tu_<start VA>.c`. The promotion commands above use the proven shell owners.
