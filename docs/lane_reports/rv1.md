# rv1 review of the CyberStorm matching method

**Fix switch ownership before assigning more allocation work.** A one-token change to a case value leaves its dispatching function STRICT. Both accepted functions I found with this dispatch pattern have the correct keys today. I also found two convincing false rejections of preceding functions. Five parked functions kept identical code and fixups under unrelated C++ TU changes. A pragma on a function actually called, and changes to the materialization of live C++ values, did change code. None yielded a new natural STRICT function.

## 2. Where the allocator gets its inputs

**Confirmed on the pinned compiler** — return-by-reference, materializing a by-value aggregate across an actual call, and handling a real scoped object can change output. **Refuted on the tested caller** — exchanging the definition order of expanded member getters determines its register tie. **Open** — which historical source or conflict record produced each exact residual home.

The local OW v2 checkout is `b0055563085902aaa7d5d1e391745fa8991219ea`. Its backend scans a block backwards to form live ranges. `AddConflictNode` de-aliases temps and prepends the new conflict. The final conflict comparator uses only descending savings. The normal list sort is an unstable Shell sort, with a different fallback if the sorting array cannot be allocated. `GiveBestReg` scores eliminated moves and can break an equal score by preferring an already given register. `RegAlloc` clears `GivenRegisters` on entry. An earlier function's register choices therefore have no direct path through that accumulator in this implementation. An expanded call in the **same** function can change uses, ranges, move affinity and the set entering the sort. R3 already calibrated the savings and ties on 10.6 and documented differences from OW, including EBX before ECX. [liveinfo.c, FlowConflicts](../../build/ref/ow/bld/cg/c/liveinfo.c) · [conflict.c:49](../../build/ref/ow/bld/cg/c/conflict.c) · [regsave.c:121](../../build/ref/ow/bld/cg/c/regsave.c) · [cgsrtlst.c:99–182](../../build/ref/ow/bld/cg/c/cgsrtlst.c) · [regalloc.c:993–1022, 1196–1214, 1321](../../build/ref/ow/bld/cg/c/regalloc.c) · [10.6 calibration and limitations](../../docs/lane_reports/r3.md)

On the C++ side, `shouldBeInlined` checks the active call stack and depth. `FEGenProc` opens a new symbol-translation block, finds the callee's virtual file, emits its saved intermediate code at that call and restores the file cursor. `tempor.c` inserts a function temporary into its temporary scope. The bound-reference code records the caller symbol and offset, attaches them to a formal for a particular inline call, and can use that symbol directly. Otherwise it fetches the reference. The same binding machinery has a path for the implicit receiver. This suggests a discriminating experiment with a **used** member, its return type and a value that survives a call. The OW paths motivate the experiment. Assembly output alone does not identify a specific private 10.6 conflict-node count. [cgbkcgrf.c:304](../../build/ref/ow/bld/plusplus/c/cgbkcgrf.c) · [cgbkmain.c, FEGenProc and IbpReference](../../build/ref/ow/bld/plusplus/c/cgbkmain.c) · [tempor.c:81–104](../../build/ref/ow/bld/plusplus/c/tempor.c) · [cgbkibrp.c:138–176, 222–300](../../build/ref/ow/bld/plusplus/c/cgbkibrp.c)

For example, the original region decoder's two scalar loads and absence of a stack copy discriminate between two plausible interfaces before trying local declaration permutations. Prior `register`, `const`, helper, and final-use sweeps already covered that cheaper family. None of the new source probes gained a parked function. ### One switch produces two proof errors

At `468316`, `ScriptStep` loads ECX=37 and EDI=`468200`, executes `repne scasw`, then jumps through `cs:[ecx*4+468248h]`. The lookup occupies **36 unrelocated word keys** followed by **37 relocated destinations**. Exhausting the scan selects destination zero. The OMF has references to the key and destination bases at offsets 2228 and 2300 decimal, with the owner public at 2448. The false orphan `468208` lies four words into the keys. The existing mapper tracks an EDI data address but covers the relocated destination run. Its orphan fallback then searches uncovered data for prologue-like bytes. S28 had already identified the spurious boundary. This review verifies the count, consumer and missing proof. ## 4. Workflow and lane assignment

**Confirmed** — the queue uses one label for different reasons to withhold work. Of 146 `no:invariant` rows, **55 have an explicit OPEN function summary and no eligible invariant verdict** in the merged notes or permitted live lane notes. They meet the fallback of three report mentions. For example, `Flic::DecodePalette` has four report mentions and an explicitly open summary. Among all classes, 33 SHAPE and 15 SAME-SIZE rows are also withheld. A negative result for one family and a decision to defer an entire function need distinct records. The saved index contains 254 rows, including the now-accepted `ScriptEvalOp`. Removing that stale row reconciles the work order's 253. These are queue counts. [Count and examples](../../build/rv1/triage.txt) · [Work filter at lines 135–145 and 191–203](../../tools/parked.py) · [Attempt ledger](../../docs/attempts.jsonl)

**Confirmed** — three classifier controls reproduce misdirection. A changed destination register in `mov r32,[absolute]` reports RELOC because the loop skips the whole instruction containing a fixup. A stack displacement changed from 4 to 8 reports OPERANDS because Capstone prints small values in decimal. Moving a NOP and changing a compare immediate can report HOMES because only a mnemonic multiset is compared. In `core_hint`, the checked-in patterns contain literal ASCII backspace and SOH bytes. `je` vs `jne` with the same target produces an empty hint. Also, matching the generic initializer name finds 71 archived reports versus 10 containing this VA. The index shows 69 reports for this one initializer. ## Recommended actions, in priority order

1. **Prove both switch arrays at the consumer and mark the full key interval before orphan discovery.** For the five demonstrated sites derive key width/count, owner-relative bases, destination count and case order from the dispatch. Check every key byte, initialized coverage, every destination binding and every relocation. Strip only an independently evidenced foreign tables-and-filler range from the preceding extent. Add regression cases for the one-token mutation, missing key, changed target and a genuine nearby function start. Expected effect: close a demonstrated false-positive path, preserve both checked accepted owners, and make the 200-byte `ScriptFormatArgs` body eligible for fresh proof. Its truncated-prefix diagnostic is not an acceptance receipt.
2. **Make both sides of a cross-object leading table use the same boundary evidence.** For `SearchGetCost`, require the next object's placement, segment alignment, observed zero gap, whole relocated table, proven filler and consumer reference. Add negatives for a nonzero prefix byte, missing relocation and non-filler suffix. Expected effect: one further 84-byte body becomes eligible without relaxing the treatment of arbitrary gaps. Rerun the normal gate after either rule change.
3. **Separate proof status, observed residue and scheduling decision.** Emit `UNBOUND` with the unproven object, `deferred:report-count` with structured attempt evidence, and explicit scope for a family vs function-level invariant. Stamp the index with ledger/source revision and drop accepted VAs before exporting targets. Mask only fixup fields, use decoded operand widths/stack bases, preserve branch mnemonics and mark HOMES as tentative unless a consistent value mapping is established. Expected effect: 55 rows acquire an accurate reason for deferral, and the type-signature initializer goes to its actual owner. Releasing all 55 for more spelling sweeps would repeat the existing expense.
4. **Spend allocation effort on one evidenced call or value lifetime at a time.** Pair the proposed change with a prediction visible in the listing, such as a pair copy, a pre-call capture, or use of a callee-preserved value. Record the extent fingerprint, target identity and fixups so a second lane can recognize identical generated output. Retire a family when those stay fixed. Future 10.6 tracing would be most informative on a specific A/B pair already known to change a home at equal shape. Expected effect: fewer duplicate builds and sharper rejections. The experiments give no basis for a projected match yield from a broader header or allocator sweep.

## Reproduction

Run from the repository root. All scratch paths are below `build/rv1`. The harness reads the existing `build/decomp/CSTORM.EXE` copy and checks it against the full pinned cs11 SHA-256 before constructing the PE image. It uses the repository's OMF reader, symbol resolver and comparator in the ordinary no-search/no-imply view, with explicit VA evaluation for the condition probes. The full-TU compiler wrapper still verifies its normal installation pins. The experimental memory variable is added only at its child-process boundary. The review made no canonical edits, published no matches and used no progress estimates from diagnostic compares.

```powershell
python -B build/rv1/conditions.py
python -B build/rv1/active.py
python -B build/rv1/audit.py
python -B build/rv1/detail.py
python -B build/rv1/ownership.py
python -B build/rv1/triage.py
```

The frozen index SHA-256 starts `dfbf8aa8d1ae`, the recovery snapshot `87c4cee43a4a`, the cs11 function map `be5549760e0f`, and the comparator `d78a95970ef9`. Compiled objects, exact generated sources, include variants and compiler logs are under the per-TU subdirectories. The changed-case source is deliberately wrong and serves only as a regression fixture.
