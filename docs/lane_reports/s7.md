## New compiler/proof findings

1. **Clamp source shape matters under wpp386 10.6 plain-oe.** Context: Refresh's division result is clamped then added to `(scale==3)`. A ternary clamp helper produces a 16-byte frame, an extra parameter spill and swapped ESI/EDI roles (942 bytes, 33 differences). Replacing only that helper with `if(n<=lo)return lo; if(n>=hi)return hi; return n;` yields the original 12-byte frame and all 939 bytes STRICT. Six helper forms were tested; `build/s7/clamp_variants.txt`, choice 2, is decisive. This is a context-specific fact, not a general rule for all clamps.
2. **Implicit versus explicit empty derived destructor.** Context: GuiControl-derived control, plain profile. Explicit out-of-line empty virtual destructor writes the derived vptr and yields 74 bytes; an inherited implicit destructor emits the 67-byte array/scalar deleting thunk without that store. The latter is STRICT at 00446848. Evidence: `build/s7/pherc.txt`, `build/s7/pherc2.txt`; source probes in build/s7/experiments.
3. **Member initializer versus body assignment controls constructor/vptr store order.** Context: HercControl with inherited virtual destructor, Watcom 10.6 plain. Assigning `value=0` in the constructor body emits vptr-before-value and changes a following function's shared zero-store tail. Using `value(0)` in the initializer list restores value-before-vptr, the original 32-byte constructor, and the following 18-byte reset function. Both constructors/destructors and all prior accepted functions then pass the promotion dry run.
4. **Proof inference can be obstructed by shifted references in DIFF functions.** All six global-object declaration variants produced byte-equal but UNBOUND fn_init (`build/s7/init_variants.txt`). A proven table data anchor removes the conflicting inferred base; final `_DATA`, CONST2, the generated destructor and fn_init all pass STRICT. This is a verifier-placement observation, not evidence of different original source segmentation.
