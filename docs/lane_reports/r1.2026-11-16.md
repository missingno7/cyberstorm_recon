## Cross-cutting finding (cross-jumping)

Three functions differ only because the original merges identical tails less, or in the other direction, than
our build: UpdateHercUpgrade (two identical case blocks not merged), UpdateMainMenuSelection (earlier copy
redirected to the later copy; ours redirects the later to the earlier), FxBeam (m4: second redraw keeps its own
copy). Not explained by case order, return/break/goto, inline wrappers, fall-through into the epilogue, `-d1`
(identical bytes for all of shell.c) or wc105 (identical). A synthetic TU always merges identical
`push; call; jmp` blocks. Next step would be a synthetic study of which two identical tails the 10.6 optimizer
pairs (and which copy it keeps) as a function of the jump-list order; that rule probably unlocks all three.

## Compiler facts (new, with evidence)

- A conditional expression used as an arithmetic operand (`(c ? f() : v) * 80 / 100`) materialises the join
  in its own temporary and copies it (`mov edx,eax; mov eax,edx`) before the multiply; the if/else and
  `v = c ? ... : v; v*80/100` forms coalesce (f_00441ca7, STRICT).
- `-d1` changes no byte in shell\shell.c (52 functions), so line markers do not block cross-jumping.
