## Object boundaries

* Hercbuy is one unaligned C++ object beginning 00416444 and continuing through the destructor at 00417f14..00417f31, with trailing alignment to 00417f34. The heuristic boundary at 00417efc cuts off generated deletion/destructor helpers. Keep these helpers with hercbuy. `plain-oe` preserves the accepted functions and matches the recovered inline-helper use. Raising the inline limit to 110 or 150 makes the copy helper inline into setup but also expands the accepted 14-byte 00417c72 wrapper; 150 also loses 004177af. Those diagnostic profiles were rejected.
* Hotseat's true initializer starts at 004243e8. The three inherited tiny functions at 004243e4..004243e8 appear to belong to a preceding object or COMDAT cluster. The final candidate retains the published ownership and source arrangement so no accepted function is lost. That arrangement lets the initializer fall through into an empty stub, removing its terminal RET: its 1,294 emitted bytes all agree, but its extent is one byte short and therefore DIFF. Six full initializer boundary probes show that separating/reordering these stubs restores the 1,295-byte STRICT initializer. A promotion dry run of `build/s27/hot_init_boundary6_best.c` instead reports `LOSS (not accepted): ['HotseatScreen::$ct']` (`build/s27/hot_init_boundary_dry.txt`). No diagnostic `code_seg` or artificial reordered ownership was adopted. Integrator work remains to transfer the inherited stubs to their actual object and then recheck both objects.
* 0046cdbc..0046ceec is an ADPCM decoder with an explicit ENTER/ES/GS prologue, unrelated sound state and no link-path evidence. It is treated as a separate, apparently assembly-origin object and parked in `_unknown/tu_0046cdbc.c`. The C++ network object begins at 0046ceec and ends at 0046d538; the next linkapp object starts there. The `multi\link.c` assertion at line 182 supports the network attribution. Assembly origin is an inference from the instructions, not proof of a recovered filename.

The hotseat prefix ownership remains an explicitly unresolved inherited boundary, not a claim that its final file is a proved whole original TU.

## New compiler and reconstruction observations

All compiler observations below concern pinned Watcom 10.6 C++ under `plain-oe`, unless specified otherwise. They are local evidence, not universal optimizer rules.

1. Multiple default arguments across distinct calls can affect frame selection. In 00425674, `GetString(0xdd3)` supplies default load=0 and the name-entry helper supplies default capacity=18. With the explicit buffer clear, this produces the target EBP frame and 119-byte STRICT body; the explicit-argument form was 120 bytes/D84. This refines the earlier default-argument observation: the defaults need not occur on the same call (`hot_small`, final status).
2. Repeated typed array expressions affect temporary layout. In 004254d5, direct `screen->teams[i]` and `screen->values[i]` expressions give the target eight-byte local frame and 234-byte STRICT body. Capturing the strings in pointer locals gives a four-byte frame and 227-byte mismatch. Restoring this function's epilogue also makes dependent validation (333 bytes) and setup (685 bytes) STRICT (`hot_profile6`, `hot_profile_direct`, `adopt_profile`).
3. Direct control expressions matter in setup: `hotValueLabels[i].SetText(...)` rather than a cached control pointer reduced 00424d60 from D105 to D2. Fixing the shared return from observation 2 then made all 685 bytes STRICT (`hot_profile_direct`, `hot_validate_goodfirst`).
4. Valid-first branch spelling recovers validation block order. `if (value <= limit)` with good image/white text before the bad image/red text/result=0 branch gives 0042500d STRICT after direct-array addressing. The equivalent bad-first spelling emits mirrored branches and D176/179 (`hot_validate_direct`, `hot_validate_goodfirst`).
5. Integer association affects LEA selection in hercbuy redraw. `selected*12+(resource+4)` yields 0041791b STRICT at 188 bytes; alternate groupings were D8/D26 (`herc_image6`). This does not imply arbitrary reassociation elsewhere.
6. The purchase call at 00417a27 needs its actual game-session argument. Reading the existing 0043c327 reconstruction established its pointer parameter; restoring `&g4a70b8`, the individual failure sounds/early returns and inline mode accessor produces 587-byte STRICT code (before: 581 bytes/D355). The description routine's supposed 00416f43 call was a mistaken name for another function's shared epilogue (`herc_buy`, `herc_text`).
7. Repeated DirectPlay global reloads, rather than cached interface/thread locals, reproduce close_link_connection's 264 bytes. In open_link_connection, a call to request_link_connection under plain-oe inlines the helper while retaining its separately called 145-byte copy and two success epilogues: both open 480 and helper 145 are STRICT. Manual expansion merged returns (474 bytes), while explicitly inline qualification removed the needed helper copy (`link_inline_probe`, `link_auto`, final promotion).
8. A fake zero-filled whole-segment array was not evidence for unrelated globals. Replacing the inherited aggregate with named extern objects and real interface/vtable types restores seven withdrawn network functions to audit-v1 STRICT, with no fake data or masks (`rewrite_link`, promotion log). This is an evidence correction, not a compiler fact.
9. Shared tails can create transitive differences: 0041733c is otherwise exact but depends on 00417219's return, and 00417842/00417c80 likewise depend on prior renderer/text epilogues. Hotseat initializer's identical emitted instructions still fail STRICT because the RET is missing. Do not promote byte-identical prefixes or invent callable symbols for internal tails.
