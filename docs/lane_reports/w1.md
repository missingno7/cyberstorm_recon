## Codegen observations from evidence

- `GlobalBlockAlloc` and `FileFreeSpace`: file-scope named constants bind to target CONST items (`errorText=0x4a4a88`, `fileRootFormat=0x48c0b8`) and allow the respective full function bodies to match STRICT. In the tested forms, inline/local formatting data did not place those items correctly.
- `RegisterAssertCallback`: `register`-qualified old-index/slot locals reduced differing bytes from 43 to 41, but did not change the first diff (`+127`) or produce the target EAX/EDX sequence.
- `SetRange`: with signed-char field access the compiler emits `movsx edx,dl`; using an `int` local emits a 32-bit immediate load, and using an unsigned-byte local emits a mask. The target stores the Boolean in DL and tests DL directly. These are source-form observations for this TU/profile.
- `Printf`: assigning `written` before `va_end` changes order at the call boundary and moves the first diff from `+68` to `+65`, while increasing total differences. The target's result save precedes both local stores.
- Plain `MemoryAllocation` wrapper: all six forwarding forms under the plain profile emit a register load followed by push; the target uses a direct memory push.
- `GetString`: after correcting field layout/stride, every tested complete body still begins with a different frame/register setup at `+4`; this points to frame/register allocation rather than the former field-offset hypothesis.

Assertion source-line immediates were preserved in candidates: file lines 140, 170, 193, 221, 354; memory line 315; strpool lines 59 and 148. No `#line` directives were used.
