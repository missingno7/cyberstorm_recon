## Per function

### 004620e0 HotbriefSetup (sim\hotbrief.c): 960 B/D667 -> 944 B (original size)/D376
The listing showed real source errors:
- the title colour and name are indexed by mission-1: `hotbriefPlayerColors[mission-1]`, `&gMenuColorMap[mission+20]`;
- the name comes from a player-slot array at 004d273e with the name at +0x10, as a struct field
  (`hotbriefSlots[i].name`, new working label; 004d273a is playerCount, i.e. SimGame slots);
- the extra `if (owner<0||owner>8)` around the ASSERT is gone; the ASSERT is still on line 204;
- the always-incremented count array is the row test, and the count of actors with `active==0` is the printed one;
- the row loop is `if (ownerCounts[row]) {...} else if (row != gRemoteActorKind-1) {...}` (taken branch first);
- the row loop uses index expressions (`&gMenuColorMap[row+21]`, `hotbriefSlots[row].name`,
  `y+100+row*0x16`); the original's [ebp-0xc]/[ebp-8]/ESI are loop-optimizer induction variables, not
  hand-walked pointers;
- the actor is typed `ActorRecord *` (actor.h, `ActorGetByIndex` is matched with that type), and the owner comes
  from `Owner()`. The accessor is what produces the original's split mov/inc/mov count update.
Remaining (allocation/scheduling):
- the viewport copy is scheduled after the x computation; the original does it right after GuiResetClip;
- with a local `s` the EBX load comes late. Casts or a typed parameter fix that, but then the two IV slots swap
  and the split count update is lost (both forms D376);
- playerCount is held in ECX instead of EAX.

## New codegen observations (not re-verified by integrator)
- ot-oe: an inline accessor result (`actor->Owner()-1`) instead of the field changes `inc dword [mem]` into a split
  load/inc/store for an unrelated counter in the same block (allocation side effect; HotbriefSetup).
- ot-oe: `mov reg,base; add reg,const` pairs for global table addresses inside loops are induction-variable starts
  from index expressions. Hand-written pointer walks give folded `mov reg,base+const` and different code.
- plain-oe: two separately written expressions for the same element address (`T &a=tab[n]; T *b=&tab[n];`) are
  CSE'd into one register plus a copy, as in the original PopInfoDrawText.
