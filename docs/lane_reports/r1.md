## Nested-default rule: source spelling and limits

```cpp
extern char *text(int, int = 1);
extern int format(char *, int);
int framed(int a) { return format(text(a), a); }
int unframed(int a) { return format(text(a, 1), a); }
```

The outgoing a argument is pushed before the inner text call. The default argument in that pending-argument context triggers EBP. A single standalone text(a), repeated separate text(a) calls, or one(text(a)) does not reproduce that trigger. format(text(1),1) in a no-formal function remains unframed; adding an unused context formal makes it framed. These controls explain why blanket default-arity experiments can miss the original frame. Neither dummy storage nor a frame-forcing compiler option is needed.

## Largest-cluster probes and rejected hypotheses

* Allocation: probe/allocation.c has three functions. Renaming locals, hoisting scalar declarations, reversing declaration order, changing int locals to long, and pointer vs reference form produce the same 160-byte code segment. These are narrow negative controls, not a universal claim that declarations never matter. In three real TUs, moving the unchanged SoundAllowed, HercFreePower and HercAddAmmo earlier leaves their respective D12/101 B, D3/144 B and D2/104 B residues unchanged. SoundAllowed standalone/first/truncated/full forms likewise all have D12 at +21. Whole-predicate pointer/reference/value/const/native-member models were also rejected (D55..104, compared with D12; lost other accepted functions). Do not repeat those predicate families without new source evidence.
* Shared layout: probe/tails.c proves forward and backward pooling; -oc/-or/-on/-ol do not isolate it in that probe. -os/-ot change its shape and total size rather than provide the desired original code. The actual GenerateMissions context difference is epilogue sharing, not internal allocation: profile_context_empty_prefix.diff.txt contains the entire instruction difference. The empty-prefix control is explicitly diagnostic and is not a proposed reconstructed TU. The declaration-order-only control leaves GenerateMissions identical despite moving its object offset.
* Switch layout: probe/switch.c has three functions. The six-entry table lies at offset 8 before choose at 0x20, so it belongs to lead’s extent. A source case permutation leaves choose’s start and total segment size unchanged but changes block order/table targets. Changing lead’s real arithmetic moves the table to 12 and choose to 0x24. This corroborates the existing table/prefix rule; no fake table or padding is supplied. These controls do not solve a DIFF target body by themselves.
* Inlining: ten published TU copies were compiled at baseline, inline_depth 1, 2 and 8. No parked code extent was newly STRICT. Shallower depths lose accepted helpers/callers in several TUs; restored final depth 8 returns the baseline. The early depth-results raw “new” lists also contain strict DATA extents and baseline shared COMDATs because that exploratory script used all extents: they are diagnostics and are not acceptance credit. Use the CODE-only toolchain results and promotion gates for claims.
* Compiler/CPU: compare wc106 -4s, wc106 -5s and pinned wc105 -4s on sound, Herc item/combat, hotbrief, hercbuy, storage, timer and actor-state TUs. wc105 preserves the baseline and unlocks no parked functions; -5s unlocks none and produces 34 accepted-function losses across the eight TUs. Thus neither a general 10.5 substitution nor a Pentium CPU profile explains these residues. toolchain-results.json records every result; no profile change is delivered.
* Class/init: six-global probes test external/inline/implicit destructors, declaration order, static visibility and copy initialization. None produces the required final EAX state update while retaining the required lifecycle. -or isolates the probe’s state-constant lifting; turning the last destructor inline-empty deletes the required state=6 rather than repairing it. Throw-spec constructor experiments require -xs and did not compile under the pinned profile. Invalid -ob, minus-toggle options and -? produce no object and are not counted as codegen trials. The spelling-generator mistakes that accidentally changed destructor parameter lists were compile errors, not evidence.

The earlier “all functions in between must be correct” tail note should be used as a relative-placement condition, not as a demand that all their instructions already be STRICT. The accepted SoundReleaseList/ShellSoundShutdown already jump into the later, still-DIFF SoundPlayDefault tail. Its suffix coordinates can match while its eligibility body differs. This is why pooling needs explicit owner/offset analysis rather than repeated return-spelling experiments.
