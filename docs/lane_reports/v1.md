## F1 — own static initialized objects bypass item/segment proof through extern bindings

**Severity: high. Wrong source remains STRICT, promotion succeeds, full verification succeeds.**

Control `memory_literal.c` changes one byte of `src/io/memory.c`'s `errorText`: `Ran out of memory` -> `Ran out of memorz`. Compile-as `io\memory.c`, profile `ot` (`wpp386 -4s -s -oxt -bm`).

```powershell
python -B candidates/v1/audit.py memory_good memory_literal
python -B candidates/v1/verify_candidate.py memory_literal
```

Exact relevant output (`memory_literal.log`):

```text
[STRICT  ] _TEXT        CODE  size 0x0098
    STRICT   0047eb50 +72    GlobalBlockAlloc (bound)
[UNPLACED] _DATA        DATA  size 0x0052
src/io/memory.c: 3 strict functions (152 bytes), new 0, lost 0
dry run OK (add --publish to accept)
promote rc 0
VERIFY function/VA/size predicate losses []
```

`memory_literal.verify.log` ends `VERIFY OK`. The oracle target is `004a4a88`, bound as `errorText` / `W?errorText$n[]xa`. The object's own LPUBDEF is at `_DATA+0`, local=true; Watcom nevertheless references it through an extern of exactly that mangled name. `_DATA` is never placed or checked. Analogous controls `assert_initializer.c` (`CyberStorm` -> `CyberStorn`) and `menu_initializer.c` (edit key 28 -> 29) also pass dry promotion and the verifier's existing function predicates.

**Root cause:** `tools/compare.py:309-319` resolves externs from the database before checking whether the object itself defines the symbol, and accepts the resulting VA without proving the definition's initialized bytes. `tools/symbols.py:121-140` permits an unscoped extern lookup to find the existing unscoped hypothesis. Placement of the public uses scoped local resolution at compare.py:152; reference resolution does not. Consequently the reference is bound while its defining object remains unplaced. `promote.py:70-80` and `verify.py:39-51` only guard function records.

**Proposed minimal conservative fix** (diff proposal only): check own initialized definitions before trusting an extern binding. This short version deliberately leaves objects containing fixups UNBOUND until the recursive data proof in F2 is available.

```diff
--- a/tools/compare.py
+++ b/tools/compare.py
@@
         if m & 3 == 2:
             name = self.m.externs[d]
             va, how = self.res.resolve(name)
+            if va is not None:
+                for pn, psi, po, local in self.m.publics:
+                    if pn != name:
+                        continue
+                    ps = self.m.segments[psi]
+                    if is_code(ps) or is_bss(ps):

+                            or not all(ps.covered[po:end])
+                            or self.img.read_va(va, end - po) != bytes(ps.data[po:end])):
+                        return None, None, name
```

Longer-term, route own externs through their local/public identity first, and prove the entire owning object after relocation. Do not solve this by marking data hypotheses matched or by trusting the local name alone.

**Proposed test_gate negative:** compile the unchanged memory TU, assert GlobalBlockAlloc STRICT; change the single error-text byte and assert GlobalBlockAlloc is not STRICT. Assert that dry promotion rejects the loss and `verify` with that source substitution fails. Add the analogous C-front-end `assertProgram` test to cover unmangled local externs.

## F2 — inferred/bound initialized-data targets are accepted despite DIFF data

**Severity: high. Wrong source remains STRICT, promotion succeeds, full verification succeeds.**

`memory_const.c` changes only the diagnostic filename argument from `__FILE__` to `"io\\memorx.c"`, preserving its length and original line count. This differs from F1: the altered bytes are in a **placed CONST segment**, and the comparator explicitly detects their mismatch.

```powershell
python -B candidates/v1/audit.py memory_good memory_const
python -B candidates/v1/verify_candidate.py memory_const
```

Exact output:

```text
    STRICT   0047eb50 +72    GlobalBlockAlloc (bound)
[DIFF    ] CONST        DATA  size 0x000c @ 004a4ba8 (inferred)
    DIFF     004a4ba8 +12    <segment start> (inferred) 1 bytes differ, first at +8
src/io/memory.c: 3 strict functions (152 bytes), new 0, lost 0
dry run OK (add --publish to accept)
```

The standalone compare CLI returns nonzero for the DIFF segment, but the callable comparison reports are consumed by promotion/verification without that protection. `try.py` prints `# 3/3 extents STRICT` while also printing `[DIFF] CONST DATA size 0xc`. The full verifier ends `VERIFY OK`.

Independent fixup-bearing variant: `menu_vftable.c` swaps the order of GuiControl's `Reset` and `Draw` virtual declarations. Fourteen emitted vftable COMDAT data segments become DIFF while the same 56 accepted functions remain STRICT. Dry promotion prints `new 0, lost 0` and succeeds; full verification also succeeds (`menu_vftable.verify.log`). Constructors now install wrong virtual-slot contents despite their pointer fields comparing equal.

**Root cause:** compare.py:183-207 infers data placement from oracle fields without proving the bytes; compare.py:291-295 immediately treats any such placement as a resolved target. Data evaluation at compare.py:402-427 is independent of the caller's verdict. Bound vftable externs have the F1 path as well. `promote.py:131-153` silently drops a formerly recorded STRICT data segment when it becomes DIFF; `verify.py:39-51` never checks `ent['data']`. The rollback check at promote.py:189-191 also checks only functions. These violate STRICT condition 3's initialized-data-byte requirement, not just deferred whole-TU ownership.

**Proposed minimal fix:** require a successful relocated data proof before returning a segment-data target. A conservative cycle guard keeps mutually recursive unresolved data UNBOUND; proving those cycles simultaneously can be a later coverage improvement.

```diff
--- a/tools/compare.py
+++ b/tools/compare.py
@@
         self.data_conflict = set()
+        self._proving_data = set()
@@
+    def _data_proven(self, si):
+        seg = self.m.segments[si]
+        if is_bss(seg):
+            return True
+        if si not in self.base or si in self._proving_data:
+            return False
+        self._proving_data.add(si)
+        try:
+            return self._evaluate(si, 0, seg.size, self.base[si][0])["status"] == "STRICT"
+        finally:
+            self._proving_data.remove(si)
+
     def target(self, f, site):
@@
             if is_code(seg) or d in self.base:
+                if not is_code(seg) and not self._data_proven(d):
+                    return None, None, seg.name
                 va = self.va_of(d, disp)
```

Apply the same proof to own initialized extern definitions (F1), including vftables. Separately add ledger-data loss checks to promotion, verify, and rollback: every previously recorded data segment must still be STRICT at the same base and size. Simply rejecting every TU that contains any DIFF data would stop these examples but unnecessarily reject unrelated incremental function work; caller dependencies and previously accepted data are the relevant obligations.

**Proposed test_gate negatives:** (a) the memory_const mutation must make GlobalBlockAlloc non-STRICT; (b) virtual-order mutation must invalidate constructors that install the affected vftables, or explicitly fail acceptance of the previously recorded table; (c) verify must fail when a recorded data segment becomes DIFF even if every recorded function still matches. Positive vftable tests must apply their own fixups rather than comparing raw pointer bytes.

## F3 — a wrong switch table can leave its owning function STRICT

**Severity: high for per-function certification; existing-TU promotion catches the predecessor's loss.**

`shell_jumptable_entry.c` swaps screen cases 27 and 29 in `Shell::Event`: case 27 incorrectly uses HercBuyRender, and case 29 uses ShellStorageRender. It changes case bindings, not the bodies of the handlers.

```powershell
python -B candidates/v1/audit.py shell_good shell_jumptable_entry
```

Relevant exact comparison (`shell_jumptable_entry.log`):

```text
DIFF     0040693b +281   Shell::RestoreMenu (bound) 2 bytes differ, first at +233
STRICT   00406a54 +503   Shell::Event (bound)
LOSS (not accepted): ['Shell::RestoreMenu']
promote rc 1
```

The changed candidate table fields are at `_TEXT+0x2cb0` and `+0x2cb8`; their low bytes exchange `ac` and `a0`. `Shell::Event` references the table with a code-segment fixup at candidate offset `0x2ec5`, `SEG+0`, addend `0x2c48`; its oracle site is `00406c39`, target table `004069bc`. The entire table lies **before** Event's public start, inside the predecessor's public interval. `build/funcmap/cs11.json` explicitly gives Event `jumptables: ['004069bc']`. Both old addend fixes work here: the table's changed bytes are detected, but in the wrong function's certificate.

**Root cause:** compare.py:128-136 partitions exclusively at publics; code targets at :281-289 are resolved from placement without checking the referenced table. Thus Event's source-level switch dispatch can be wrong while its public extent remains STRICT. The docs' public-interval definition currently permits this mechanically; it is insufficient to certify a function including its owned jump tables. Do not mistake this for a failure to apply the newly fixed SEG addend.

**Proposed minimal fail-closed fix:** use the existing function-map table ownership to withhold STRICT for a function with an external, unproved table. A complete repair should attach an additional relocated table-range proof to the owner; do not count its bytes twice.

```diff
--- a/tools/compare.py
+++ b/tools/compare.py
@@
         else:
             st = "STRICT"
+        if st == "STRICT" and is_code(seg):
+            fm = Path(__file__).resolve().parent.parent / "build" / "funcmap" / f"{self.img.name}.json"
+            rows = json.loads(fm.read_text())["functions"] if fm.exists() else []
```

This is intentionally conservative: it also withholds the unchanged owner's certificate until external-table proof is implemented. That proof should derive table length from oracle relocation/table evidence, locate the candidate through the actual effective fixup target, apply all table-entry fixups, compare every byte/site, and associate failure with Event.

**Proposed test_gate negative:** reproduce the case swap, assert Event itself is non-STRICT, not merely RestoreMenu. After adding table-range proof, require unchanged Event STRICT as the positive control. Also test a partial TU containing Event and its leading table but omitting RestoreMenu; it must not gain a false certificate by dropping the predecessor from the ledger.

## F5 — promotion does not enforce its documented size-loss guard

**Severity: medium. Dry promotion accepts a previously counted-byte loss; old-ledger verify detects it.**

`fog_segment_shrink.c` isolates FogNoOp using legal `#pragma code_seg("AUDIT_TEXT", "CODE")` / reset directives. ```powershell

The old ledger records FogNoOp size 16; the new extent is size 1 with `tail_fill=15`. Full verify against the existing ledger correctly prints `FAIL src/terr/tfog.c: ['FogNoOp']`. **Root cause:** promote.py:77-81 checks old status and VA, omitting size. Its record creation (:151-152) replaces the size; rollback (:189-191) checks only the replacement. This contradicts docs/verification.md's “no previously accepted function may lose STRICT, VA or size”.

```diff
+        if (not now or now["status"] != "STRICT" or now["va"] != e["va"]
+                or now["end"] - now["off"] != e["size"]):
```

**Proposed test_gate negative:** this segment-split candidate must be rejected as `LOSS ... FogNoOp` without --accept-loss. Assert old size 16 and new size 1 so the control cannot silently stop exercising the guard. Keep the legitimate one-function partial control as an independent positive comparison test.

The jump-table entry control is **not** listed as holding: the predecessor catches the TU regression, but Event's own certificate is false (F3). The vftable COMDAT test is likewise a demonstrated bypass (F2), not COMDAT coverage success.

Code-path review also covered:

* Placement/segment completion: extents may intentionally have different segment bases for incremental recovery. `_complete_code` only fills unplaced extents when placed bases agree. Do not treat reordered functions alone as unsoundness at the deliberately per-function proof level. F4 is the independent missing-start check.
* Masked search: masks only guide placement; byte/fixup/relocation/extent checks subsequently run. Its six-byte anchor minimum and ambiguous-hit refusal are diagnostic limitations, not observed false certificates. A unique suffix hit would still need F4's start check.
* Implied bindings: only UNBOUND byte-equal extents contribute; targets must agree and be plausible. Existing resolver bindings take priority. New aliases and prototype/mangle disagreement are explicitly permitted by the current contract. F6 is a concrete over-rejection.
* Item proof: effective `disp + data-field addend` is now used in both bounds and target lookup. Its printable-prefix/NUL heuristic still lacks type evidence for distinguishing arbitrary initialized binary objects from strings. Raw `_item_bytes` does not apply the item's own fixups or check their relocation sites. These deserve dedicated binary-object/pointer-table fixtures; no new oracle-backed false certificate from those particular paths was established here.
* Self-relative data: base inference normalizes `field + site + 4`; segment-based evaluation uses the same arithmetic. Per-item mode explicitly disables it at compare.py:304 (`if not f.self_rel else None`), so a correct self-relative data reference in a conflicting layout cannot use item proof. No accepted-source mutation emitted an oracle-equivalent self-relative data fixture; this remains a code-review coverage limit, not a claimed reproduced finding. A future test should use real self-relative OMF, prove target bytes at `site+4+signed(field)`, and require no HIGHLOW relocation at its field.
* BSS: bound-target addend mutation is caught. BSS allocation/order/size itself is explicitly deferred TU-level work; the comparator reporting BSS rather than proving an initialized image is not claimed as a new function-level bug.
* Rollback: ordinary bad-function statuses compare with new records and restore three files. There is no exception-safe rollback around the post-write rebuild or subsequent save operations. Under the no-publish constraint, failure injection into that path was not performed. F1/F2 can evade its existing function predicates; F5 replaces the old size before checking it.
* Source policy: top-level regex checks strip comments and catch the listed obvious forbidden forms. Includes/preprocessor-generated spellings are not recursively policy-reviewed; the working contract explicitly reserves non-obvious code-byte substitutions for review. No byte-emission control was added to src or used to obtain any finding.

The report does not certify whole-TU layout, natural linking, unknown malformed OMF records, or an exception-safe publishing transaction. Those limits do not weaken the six concrete reproductions above.
