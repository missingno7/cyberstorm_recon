## Codegen findings for the integrator

All observations below use pinned Watcom C++ 10.6, `--profile plain`, `--as 'shell\hbupgrad.c'`.

1. **The RichTextDraw defaults explain the frame, without -of.** Writing all 16 arguments kept the ESP-based local shape that blocked w14. Declaring the trailing font/ignore/first/last defaults and omitting them produces the original EBP frame. c456 (148 B) and c4ea (68 B) are STRICT; c3ca now differs only in its shared-tail displacement. The six description-frame probes confirm that at least two omitted defaults retain the frame, while one or zero do not. This resolves the earlier -of-only diagnostic, rather than recommending a new profile.
2. **An inline comparison accessor preserves scalar boolean materialization.** `inline int UpgradeIsOpen(char *p){return *(int *)(p+0x10)!=0;}` in an if produces `cmp / setne al / and eax,0xff / jcc`. A direct field comparison removes the scalar materialization; retaining an unsigned-long result temporary adds conversion instructions. The conditional-return close spelling made 19875 STRICT at 78 B. The same guard shape recovered the open, update, and renderer guards.
3. **A temporary inside an inline member setter can change address allocation even at equal function size.** In SetMode, a direct `attributes=(attributes & mask)+mode` made ac2a (302 B) and ad58 (317 B) STRICT. Capturing through a named unsigned-long temporary left 24 differences in each: index/value registers were exchanged and the second address stayed indexed instead of being materialized. Seven measured alternatives retained in mode.tpl.c. This is contextual: standalone global color handlers still need the w14 scalar-load/store form.
4. **Small integer conversion and accessor boundaries matter to CSE.** In c096, redundant `(unsigned)i` and unsigned page-index casts caused a second stack slot and extra widening; ordinary integer promotion removed the slot. A native `UpgradeChoice::Name()` accessor restored the first call's temporary allocation. Keeping Cost as a field (rather than a native Cost getter) supplied the remaining full pointer/address shape and made the entire 335-byte function STRICT. The four item-getter plus six choice-cost probes isolate this context; this is not a universal rule to add getters.
5. **The SetPrefix caller uses an unsigned-byte formal.** Declaring the caller-side method parameter signed char inserted `movsx` before the push and changed several saved-register choices. Unsigned char reuses the widened array index; b13b is STRICT at 337 B. The different mangled prototype is implied by its bytes under its own binding, rather than resolved by readable label.
6. **Global declaration order reproduces initialization state.** Native global Menu objects, arrays, and range-widget objects generated the full 1,202-byte 418ef0 extent, including the runtime module registration and all 41 state advances. A range without a destructor followed by its bar contributes one state advance after both constructor calls. Module `_DATA` and both array type signatures also prove STRICT. Actual screen/range class names and generated nonmatching wrappers remain provisional.
7. **PlyKey copy spelling and local order are visible.** Declaring the destination before the source and assigning low/high members separately produces four scalar moves rather than movsd and avoids extra ESI/EDI saves. c6dc is STRICT at 199 B. Struct initialization produced a 196-byte mismatching function.
8. **Dispatch label source order survives lowering.** The large state-layout switch has physical cases 1/2, 4, 3, 5, 6; restoring this order plus a native char-pointer formal recovered its complete 2,718-byte body. Its table address remains DIFF. The smaller c52e switch similarly needed source case 5 before 3 for STRICT; adding otherwise empty states changed its lowering and failed.
