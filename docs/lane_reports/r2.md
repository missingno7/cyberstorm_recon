# Lane r2: register and stack allocation research

STATUS: partial

Four new function-level STRICT candidates, **1,359 bytes across two TUs**, with every previously accepted function preserved. **0043a97f HercAddAmmo (104 B)** captures the memory multiplicand before a multiply/divide expression, fixing two divisor-register bytes without adding an instruction. A reduced source probe reproduces that allocation effect and its profile dependence. A separate inline-formatting helper change restores shared-tail distances for **0041be20 (630 B), 0041c1e5 (485 B), and 0041c3ca (140 B)**; those are layout fixes, not allocation fixes. The broader goal of an allocation idiom unlocking at least three parked functions in different TUs is **not achieved**. Cross-TU controls below are mostly negative validations, not three positive allocation reconstructions.

All work stayed under `candidates/r2/` and `build/r2/`. No publishing, canonical edits, git changes, target execution, direct asset access, or background helper was performed. Compiler and oracle access was through the repository tools. No repository-wide progress total is claimed.

## Method and reproducibility

Read `docs/worker_brief.md`, `docs/verification.md`, `docs/codegen_rules.md` (including the newest r1 rows), and `candidates/r1/REPORT.md`. Used the r1 inventory as a research index, then rebuilt published `src/` copies, rather than earlier workers' candidate bodies. Excluded all TUs named in the work order. Selected **16 functions from 14 TUs**, all with mapped extents under 200 bytes. `sample.json` records profiles, AS paths and accepted functions at baseline; `input-hashes.json` records the starting inputs. The sample includes one inventory misclassification: MenuDrawText is a shared-tail placement residue, not an allocation mismatch.

`run.py` redirects `CSTORM_SCRATCH` and the tools' temporary directories into `build/r2`; it changes no compiler options, placement, comparison, promotion policy or oracle. Every command below can be confined to this lane by replacing `python tools/TOOL.py` with `python -B candidates/r2/run.py TOOL.py`.

Reproduction scripts:

```text
python -B candidates/r2/research.py
python -B candidates/r2/experiments.py
python -B candidates/r2/captures.py
python -B candidates/r2/boundaries.py
python -B candidates/r2/result_helpers.py
python -B candidates/r2/assess.py
python -B candidates/r2/assess.py boundary-experiments.json
python -B candidates/r2/assess.py result-experiments.json
python -B candidates/r2/probe_capture.py
python -B candidates/r2/validate.py
```

`research.py` regenerates baseline copies, so it intentionally replaces both delivered edits with their published seeds; restore ammo from `build/r2/factor-ammo/tu_0043a294.c` and the upgrade helper from `build/r2/result-cost/v3/hbupgrad.c` afterward. The delivered upgrade copy formats that same code over the available lines; the fresh gate confirms unchanged codegen. The other scripts generate full-TU templates and scratch variants, not canonical source. `assess.py` saves each rendered source, compiler log, object and complete comparison under `build/r2/<tag>/v<N>/`. Use those saved sources for historical reproduction if concurrent integration changes published input.

There are **27 eight-choice full-TU templates / 216 successfully compiled choices**, including their baseline controls, plus **24 reduced-probe builds** (eight source forms at three profiles). This is an experiment count, not a count of independent hypotheses or accepted functions. Initial script mistakes (one missing Python import, multiline template formatting, a pointer type, and a function selector accidentally selecting a call site or skipping inline definitions) were corrected and rerun. Final assessment manifests have **zero compiler errors**. These mistakes provide no compiler evidence.

### Collateral shared-tail candidate: shell/hbupgrad.c

```cpp
static inline char *UpgradeCostText(char *text, const UpgradeEntry *entry) {
    sprintf(text, g48ab34, entry->cost);
    return text;
}
inline void UpgradeCostList(char *screen) {
    for (unsigned char i = 0; (int)i < *(int *)(screen + 0x3d8); ++i)
```
